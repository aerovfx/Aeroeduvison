## OpenFang‑style Agent API (for Aeroedu)

This document defines the **expected HTTP API** exposed by the Agent OS (OpenFang or an Aeroedu‑specific clone). Aeroedu calls these endpoints; they are implemented in Rust outside this repo.

---

### Base URL

- Dev: `OPENFANG_BASE_URL=http://127.0.0.1:4200`
- Prod: internal service DNS, e.g. `http://agent-os:4200`

All examples below assume `OPENFANG_BASE_URL` is configured in Aeroedu.

---

### 1. `GET /api/health`

**Purpose:** basic liveness check for the Agent OS.

- **Response 200:**
  ```json
  { "status": "ok", "uptime_sec": 12345 }
  ```

---

### 2. `GET /api/agents`

**Purpose:** list available agents/Hands, including the Aeroedu‑specific ones.

- **Response 200 example:**
  ```json
  [
    {
      "id": "aeroedu_camera_guard",
      "name": "Aeroedu Camera Guard",
      "description": "Monitor camera and recording health",
      "status": "active",
      "last_run_at": "2026-03-16T04:00:00Z"
    },
    {
      "id": "aeroedu_exam_analytics",
      "name": "Aeroedu Exam Analytics",
      "description": "Analyse exam matrices and performance",
      "status": "active",
      "last_run_at": "2026-03-16T04:05:00Z"
    }
  ]
  ```

Implementation detail (Rust): typically backed by the OpenFang `agents`/`hands` registry.

---

### 3. `POST /api/agents/{id}/message`

**Purpose:** trigger a run or send a task to a specific agent/Hand.

- **Request body (generic envelope):**
  ```json
  {
    "message": "run_once",
    "payload": {
      "scope": "all"  // or classId, grade, etc. depending on the Hand
    }
  }
  ```

- **Response 200 example:**
  ```json
  {
    "status": "accepted",
    "agent_id": "aeroedu_camera_guard",
    "run_id": "run_01HV...",
    "queued_at": "2026-03-16T05:00:00Z"
  }
  ```

---

### 4. `GET /api/reports/{handId}`

**Purpose:** fetch recent reports generated by a given Hand.

- **Example:** `GET /api/reports/aeroedu_camera_guard`

- **Response 200 example:**
  ```json
  {
    "hand_id": "aeroedu_camera_guard",
    "reports": [
      {
        "id": "rep_01HV...",
        "created_at": "2026-03-16T04:00:00Z",
        "format": "markdown",
        "title": "Camera Health Report – 16/03/2026 04:00",
        "summary": "3 critical cameras, 5 degraded, 2 classes without reliable coverage.",
        "content": "## Executive Summary\\n..."
      }
    ]
  }
  ```

The underlying storage and retrieval logic is owned by the Agent OS.

---

### 5. Authentication & Security

- Aeroedu includes an internal token on outbound calls:
  - Header: `Authorization: Bearer ${OPENFANG_INTERNAL_TOKEN}`
- Agent OS validates this token and rejects unauthorised clients.
- For webhooks back into Aeroedu, Agent OS likewise uses a shared secret or mTLS.

---

### 6. Implementation Notes (Rust side)

These endpoints are expected to be implemented in the Rust Agent OS (OpenFang or clone) by:

- Registering routes (e.g. in `server.rs` / `routes.rs`).
- Using the existing kernel/agent registry to:
  - Enumerate agents/Hands.
  - Enqueue or trigger runs.
  - Read stored reports for each Hand.

This repo only **documents** the contract; the actual Rust implementation lives in the OpenFang codebase.
